# VINote App

[English](README.en.md) · [运行、打包与部署](docs/build-and-deployment.md) · [Android 验收记录](docs/android-device-check-20260923.md)

React Native Community CLI 原生应用，使用统一的 React Native 原生组件与中性色主题；不使用 Expo。Android 和 iOS 均有原生录音、导入与音频切分实现；具体后台行为需要按系统版本真机验收。

## 当前架构与功能

- 当前 App 使用记录 / 笔记 / 助手 / 我的四入口。记录分为录音操作区、搜索筛选与历史列表；笔记按记录聚合，项目与归档在笔记内部，历史版本在详情；文字笔记有独立整理入口。我的按账号、模型、存储与同步、连接与工具、外观分区。飞书和 MCP 统一位于连接与工具，并从详情交付 / 助手提供上下文入口。
- 录音页的开始、结束与重试保存按钮固定在底部；详情中的录音时间引用可以点击回听。改名在同一个底部面板中完成，失败保留输入，面板随键盘调整。原录音读取失败可重新加载；详情返回进入时的工作台、录音库或助手页面。
- 账号直接连接部署配置中的 Supabase，同桌面端使用同一账号体系；支持邮箱密码登录、验证码注册和邮箱验证码重置密码。访问/刷新令牌保存到系统 Keychain。退出只清除本机凭证，两端可以同时登录。登录及原有生成直接连接云服务；共享工作空间、飞书和 MCP 需要管理员配置的集成服务。
- 会议模型直接调用 VILab：`/v1/models`、`/v1/default-models`、`/v1/asr/transcriptions`、`/openai/v1/chat/completions`。模型选择按账号保存在本机；处理开始时固定选择。
- 点击开始后直接录音，不预选生成模式或模型；结束先保存原音频，再选择仅保存或选择 ASR/LLM 模型生成纪要。支持修改名称、播放、系统分享/保存文件、确认删除以及系统文件选择器导入音频；导入后也可立即选择模型生成纪要。
- 默认名称为本地开始时间＋会议录音；生成纪要时另以录制或导入时间＋内容主题命名。手动录音名称不覆盖。导入记录使用导入时间，不推断会议实际发生时间。录音标题和纪要标题分别管理。
- 音频准备为 16kHz 单声道 PCM16 WAV。录音转写读取 `/v1/models` 中所选模型的 `capabilities.recordedAudio` protocol 1 / `adaptive_pause` / `service_budget` 策略，按服务配置的单会话 PCM 字节预算（640..64MiB 偶数字节）顺序提交。预算来自服务调用方式，不是模型时长上限，不按模型名固定秒数。规划扫描复用已有专属 PCM reader，每次最多6400字节并明确关闭句柄，保持20ms/320-sample均方能量窗；单遍更新running peak，仅frameStart达到预算末1/3起点才更新最低能量与持续240ms静音中点，规则与Python planner相同。没有持续静音时用实测最低能量窗中点，不伪称停顿。当前RNFS Android read未关闭输入流，不能作为64k绕过路径；Android缺专属reader时失败关闭，64k桥接优化留待单独原生变更。区间按采样点连续无重叠，保持原模型，不提供猜测的词时间。缺少或无效策略时提示“当前服务的录音转写尚未就绪，请更新服务后重试”并阻止音频提交；原成功检查点继续可用。
- 每次任务固定 ASR/LLM 选择。无论资料长短，完整转写与独立说话人证据一次交给显式选定的总结模型成稿，再对照完整原资料做整体核查；不按固定字符数、段数或模型名称拆分，不自动换模型或重试推理。超出服务context时保留原资料并报告原服务错误，不自动降级分段。纪要按实际主题和讨论脉络组织，段落、要点、小标题按需组合，不强制栏目、顺序或字数；保留必要背景、观点理由、关键参数、条件、不同意见及明确待办，完整转写另外保存。各阶段保存检查点。摘要失败不自动重试；录音 ASR 每段只调用一次，提交前持久化 inFlight 区间，只有已确认 final 与正文落盘才移除标记。失败不自动重放或换模型；旧 unknown 与中断未确认区间禁止重试，不覆盖原始证据。进程中断后保留 pending 检查点，由用户手动继续或重试，不在登录或前台恢复时自动启动重型语音。没有任意时刻后台生成保证。
- 同账号模型列表缓存 60 秒并合并同时请求，点击“刷新模型列表”强制联网；账号切换隔离缓存。录音元数据的 `processingTimings` 保存准备、切片、ASR 请求（含上传和服务响应）、总结各轮及总耗时，不含媒体内容或凭据；并发请求耗时不能简单相加作为总等待时间。
- 同时显示转写与说话人分析各自的处理状态；一条生成任务完成或失败后再处理下一条，避免多个完整音频模型同时占用内存。本机说话人耗时另记入 `speaker-analysis`，有效检查点复用时标记 `cacheHit`。
- 同一份录音可反复生成纪要，每次保留为独立的版本 1、版本 2等，录音库可分别打开。纪要支持搜索、Markdown 阅读、改名、删除，并可通过系统分享菜单导出当前版本的 `.md` 文件；删除单份纪要保留原录音及其他版本。同一记录在笔记列表聚合为一条，全部生成版本与编辑历史保留在详情。
- 会议、笔记及其版本在当前设备管理；已取消跨设备自动同步，客户端不再向 `/api/workspace` 推送或拉取内容。原录音与处理检查点保留在手机，重要音频请先导出；卸载或清除应用数据会丢失设备上的内容与原音。
- 笔记页“链接或文件转笔记”支持公开视频链接（含 B 站分享文字）及音视频／TXT／MD／SRT／VTT／JSON。先保留选中文件，用户点击生成才上传当前内容服务；已接收任务可返回重入查看，同一任务查询或保存失败不会重新提交生成。PDF/Word、普通文章和需登录文档暂不直接提取。正式包需管理员配置具备生成接口的 integrationBaseUrl；当前开发版使用 USB 转发的电脑服务。
- 集成请求由 `src/lib/integration.ts` 统一处理。DEBUG 使用 `http://127.0.0.1:8900`（USB 开发由主进程建立 adb reverse）；release 仅使用管理员配置的 `deployment.integrationBaseUrl`，缺失明确不可用。401 最多刷新 token 一次，不绕过鉴权。生成保存冲突保留返回正文供另存，离线/409 不伪报同步成功。
- 共享界面使用原生 Animated：短距离入场、标题揭示、选中 pill、按压反馈和忙时条形 loading；尊重减少动态效果，loading 在后台停止，正文不逐字重播。原生视觉与类型检查由主 agent 串行验收，代码修改不代表已验收。

## 网络与平台边界

测试包内置 VILab `http://192.168.1.143:9876`，正式包内置 `https://api.orulink.ai`；账号统一使用 `https://supabase-vinote.orulink.ai`。Android 和 iOS 的账号请求遵循系统网络设置，构建命令自动选择部署配置。旧账号需在新项目重新注册，旧数据暂留旧项目。

ASR 明确返回 Aliyun 或 Volcengine 空转写错误时，保留为空分段并继续后续音频；全部分段都为空时仍报告未识别到有效语音，其他服务故障沿用重试与失败处理。

公网 VILab 已配置 HTTPS 域名；域名配置通过不代表 DNS、证书、上游鉴权和大文件上传已验收。测试包仍需能访问内网服务。

Android 前台麦克风服务用于切换应用及锁屏录音；转写和总结期间使用 dataSync 前台服务及通知，受系统配额和电池策略约束。iOS 配置了后台音频能力；纪要处理只申请有限的后台执行时间，长会议切后台后可能被系统暂停，回到 App 后从检查点继续。来电、麦克风争用、进程被杀和低磁盘可能中断录音；中断文件不一定可解码。会后本机 sherpa-onnx 说话人分析与云端转写并行，两份独立时间轴分别保存；一份失败保留另一份，重试复用完成结果。编号只用于本次录音，重叠归属保留不确定性，分钟转写不伪造逐句归属；详情可查看发言时间轴并改名。Android 包已包含原生模块；iOS 原生实现与 Pod 接线已提供，仍需在 macOS 构建和真机验收。

登录来源请求头仅供后台备注，不作为权限依据，不向用户展示。App 直连 Supabase，**尚未写入桌面后端 `auth_login_events`**；不能声称已完成统一跨端登录审计。旧版桌面 JWT 不复用，升级需重新登录；缺少所属账号的旧录音不自动迁移。

## 快速开始

需要 Node >=22.11、npm、Android SDK/NDK、JDK 及平台原生工具；iOS 还需要 macOS/Xcode/CocoaPods。构建前会校验并准备本机说话人模型，首次下载需要 curl、tar 与联网；Android preBuild、iOS Podfile 自动运行 scripts/prepare-speaker-models.cjs，模型与 iOS 官方框架均校验 SHA-256。完整说明见[运行与打包](docs/build-and-deployment.md)。

```sh
npm ci
npm run config:check
npm run android:test:debug      # 内网 VINote Test + Metro
npm run android:test:apk        # 内网独立 APK
npm run android:vinote:debug    # 公网 VINote Dev + Metro
npm run android:vinote:apk      # 公网正式 APK，需发布签名
```

源码调试依赖 Metro；若手机不能访问开发机，可执行 `adb reverse tcp:8081 tcp:8081`。公网 Debug 使用独立包名，避免调试签名覆盖正式版；两种 APK 均内置 JS。详见[运行与打包](docs/build-and-deployment.md)。


### 会议总结流式传输

总结各阶段使用公网 OpenAI 兼容 SSE，通过原生 XMLHttpRequest 增量接收并显示已接收字数。只有收到完整结束标记且正常结束的结果才写入检查点；断线或截断不会保存半份纪要。原有完整转写和成功事实可继续复用。单次流式请求总上限 15 分钟，仍受服务可用性及后台限制。处理计时另记录完整转写墙钟与总结首内容到达时间；首内容时间包含请求启动、网络及服务等待，并非纯模型延迟。流式传输解决长时间无响应的传输风险，不保证模型或 ASR 请求本身变快。

## 记录工作台与飞书设置

新版首页整合录音和纪要的搜索与状态筛选；详情提供纪要编辑/历史、分段逐字稿跳转、基于资料的对话及飞书交付。飞书设置采用浏览器用户授权，默认个人云文档，支持本人和指定群同时通知。`config/deployment.{test,public}.json` 新增 `integrationBaseUrl`，必须由管理员指向 VINote 共享集成服务；留空时明确提示未启用。企业 App Secret 仅放服务端，不能放入 App。缺少原 operation ID 的旧自动交付队列保持本机记录，恢复入口明确提示待核验，不自动创建文档或重发通知。通知失败不重新生成纪要。设备原件不会自动同步到桌面，逐字稿时间仅为实际分段起点。详见父仓库 docs/feishu-integration.md。

### 本机内容与账号核验

首次成功线上核验会保存不含凭证的归属证明。之后同账号、同认证与集成 Origin 启动时可先查看已保存本机内容，继续纯本机编辑及原件播放/导出，同时核验账号。缺少或不匹配证明的旧缓存保留并明确提示待核验，不伪装成空库。核验网络请求及最多一次刷新共用 8 秒取消信号；本机 Keychain/存储操作仍完整等待，不通过超时竞赛遗留凭证写入。

核验前远端写入、授权业务读取和私有附件读取暂停，包括会更新本机缓存/游标的 workspace 同步 GET；它们不全部称为“云端写入”。账号服务故障保留本机工作台，确定登录过期要求重新登录并保留本机稿；已在工作台的录制仍可停止和本机保存，未保存前不进入重新登录。前后台、账号变更与新核验使旧请求失效，普通 token 刷新不切换身份。手动“重新核验”只核验身份；核验成功后的正常启动/前台同步仍使用原 fresh CAS，不自动重放未知 MCP、飞书或来源生成请求。新门禁已有聚焦回归与类型检查；设备冷/暖启动、后台/离线和录制中过期仍需实机复验。

USB 源码热更新：先选 `npm run config:public`，运行 `npm start -- --host 127.0.0.1`，执行 `adb -s <USB序列号> reverse tcp:8081 tcp:8081`，再 `npm run android:vinote:debug -- --no-packager --device <USB序列号>`。若 Windows Java NIO 因临时目录别名报 loopback connection 错误，可为当前启动设置 `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=<短ASCII目录>`；无需修改系统全局网络设置。

### 说话人分组与资源限制

App 的转写和本机说话人分析并行进行，两路检查点分别保留。完整发言区间分析之后，最多选取 128 个持续发言和 128 个补充发言窗口修正声音分组；每个窗口最多 8 秒，原生按窗口读取缓存，提取器使用两个线程。声音特征向量只在内存中用于聚类，不保存到纪要、检查点或发送给总结模型。短发言证据不足及重叠发言保留待确认标记，编号不能当作真实姓名。

已有原始区间检查点可跳过整段检测，特征修正成功后单独落盘；后续失败重试复用有效结果。工作台与录音库订阅同一任务进度，并按当前账号过滤。录音库的生成版本并排显示，详情独立时间轴显示区间起止并可回听改名。飞书状态未读取成功时不可提交，刷新群失败保留已选对象。

声音组需至少两段代表发言且累计有效特征时长六秒，孤立短声音继续待确认。修正版本 2 使用新的组编号，旧改名不会自动套到新组；编号仍须人工回听确认。授权核验保留未保存设置，群错误单独重试；会议对话空白回答保留问题供重试。搜索空状态可清除筛选恢复列表。

源码 Metro 限制为 2 workers，不监听根目录 android/ios 原生构建、模型与 documents 档案，JS 源码和品牌资源仍参与热更新。低内存开发机可使用 `node --max-old-space-size=768 node_modules/react-native/cli.js start --host 127.0.0.1 --port 8081 --max-workers 2`；改 Metro 配置需重新启动该服务。手机同时只处理一份完整生成任务，Windows 不代表 iOS 新模块已构建。

### 界面与录音交互

记录、助手、我的共用底部导航；飞书设置也可直接切换，离开未保存设置需选择继续编辑或丢弃。录音支持暂停/继续和时间标记，暂停不计媒体累计时长；详情保留实际录制起止、版本、编辑/交付、三个正文页签和固定播放器。飞书未配置呈现明确禁用状态，网络/群列表/保存失败分别重试并保留草稿。

正文由 AppText 统一使用打包的 Noto Sans SC，避免主题字体改变产品排版；字号仍遵循系统文字缩放。字体来源和 SIL OFL 许可见 assets/fonts/README.md。原生字体/暂停功能需重建安装包；Android已编译安装，iOS资源和源码尚需macOS构建验收。样式规范见父仓库 docs/ui-design.md。

逐条同步（2026-10-12）：新会议/笔记默认保存在此设备，详情可明确允许同步或“暂停此设备同步”。暂停停止此设备的后续上传与接收，云端和其它设备保留；原音视频及导入原文件不随正文同步。真实已有 ACK 授权可延续，未知操作只能核验原回执，404 不代表未执行。不支持新协议的旧服务会阻止新同步写入；账号或协议读取失败显示待核验。依赖云端 key 的生成能力尚不能因此冒充支持纯本机内容。
