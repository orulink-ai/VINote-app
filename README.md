# VINote App

[English](README.en.md) · [运行、打包与部署](docs/build-and-deployment.md) · [Android 验收记录](docs/android-device-check-20260923.md)

React Native Community CLI 原生应用，使用统一的 React Native 原生组件与中性色主题；不使用 Expo。Android 和 iOS 均有原生录音、导入与音频切分实现；具体后台行为需要按系统版本真机验收。

## 当前架构与功能

- v0.1.1 更新图标与中性色界面，首页提供开始录音、直接导入音频、最近录音及最近纪要；登录页精简为账号操作表单。
- 账号直接连接部署配置中的 Supabase，同桌面端使用同一账号体系；支持邮箱密码登录、验证码注册和邮箱验证码重置密码。访问/刷新令牌保存到系统 Keychain。退出只清除本机凭证，两端可以同时登录。App 不依赖电脑 FastAPI 服务。
- 会议模型直接调用 VILab：`/v1/models`、`/v1/default-models`、`/v1/asr/transcriptions`、`/openai/v1/chat/completions`。模型选择按账号保存在本机；处理开始时固定选择。
- 点击开始后直接录音，不预选生成模式或模型；结束先保存原音频，再选择仅保存或选择 ASR/LLM 模型生成纪要。支持修改名称、播放、系统分享/保存文件、确认删除以及系统文件选择器导入音频；导入后也可立即选择模型生成纪要。
- 默认名称为本地开始时间＋会议录音；生成纪要时另以录制或导入时间＋内容主题命名。手动录音名称不覆盖。导入记录使用导入时间，不推断会议实际发生时间。录音标题和纪要标题分别管理。
- 音频准备为 16kHz 单声道 PCM16 WAV；标准格式直接复制到独立缓存，60 秒内直接上传，长录音每段最多 60 秒、最多两段并发转写，结果按原顺序保存。检查点兼容旧版连续进度，也支持乱序完成；重试复用已完成段及经源文件信息、原生格式校验的音频缓存，缓存丢失自动重建，更换 ASR 模型重新转写。
- 每次任务固定 ASR/LLM 选择。8000 字符以内的转写直接成稿、对照原文核查；更长转写每块最多 6000 字符、最多两路并发提取事实，必要时分层合并，再成稿核查。纪要按实际主题和讨论脉络组织，段落、要点、小标题按需组合，不强制栏目、顺序或字数；保留必要背景、观点理由、关键参数、条件、不同意见及明确待办，完整转写另外保存。各阶段保存检查点。临时网络/429/502/503/504 错误最多自动重试两次。进程中断后再次打开 App 自动续做 pending 任务；失败任务可手动重试。没有任意时刻后台生成保证。
- 同账号模型列表缓存 60 秒并合并同时请求，点击“刷新模型列表”强制联网；账号切换隔离缓存。录音元数据的 `processingTimings` 保存准备、切片、ASR 请求（含上传和服务响应）、总结各轮及总耗时，不含媒体内容或凭据；并发请求耗时不能简单相加作为总等待时间。
- 同一份录音可反复生成纪要，每次保留为独立的版本 1、版本 2等，录音库可分别打开。纪要支持搜索、Markdown 阅读、改名、删除，并可通过系统分享菜单导出当前版本的 `.md` 文件；删除单份纪要保留原录音及其他版本。App 本地纪要标识手机来源；桌面后端另有生成来源字段，二者不是数据同步机制。
- **录音、纪要及处理检查点均按账号保存在手机本机，暂不跨端同步。卸载或清除应用数据会丢失本地内容。重要音频请先导出。**

## 网络与平台边界

测试包内置 VILab `http://192.168.1.143:9876`，正式包内置 `https://api.orulink.ai`；账号统一使用 `https://supabase-vinote.orulink.ai`。Android 和 iOS 的账号请求遵循系统网络设置，构建命令自动选择部署配置。旧账号需在新项目重新注册，旧数据暂留旧项目。

ASR 明确返回 Aliyun 或 Volcengine 空转写错误时，保留为空分段并继续后续音频；全部分段都为空时仍报告未识别到有效语音，其他服务故障沿用重试与失败处理。

公网 VILab 已配置 HTTPS 域名；域名配置通过不代表 DNS、证书、上游鉴权和大文件上传已验收。测试包仍需能访问内网服务。

Android 前台麦克风服务用于切换应用及锁屏录音；转写和总结期间使用 dataSync 前台服务及通知，受系统配额和电池策略约束。iOS 配置了后台音频能力；纪要处理只申请有限的后台执行时间，长会议切后台后可能被系统暂停，回到 App 后从检查点继续。来电、麦克风争用、进程被杀和低磁盘可能中断录音；中断文件不一定可解码。说话人区分按需求暂停，当前不提供该能力。

登录来源请求头仅供后台备注，不作为权限依据，不向用户展示。App 直连 Supabase，**尚未写入桌面后端 `auth_login_events`**；不能声称已完成统一跨端登录审计。旧版桌面 JWT 不复用，升级需重新登录；缺少所属账号的旧录音不自动迁移。

## 快速开始

需要 Node >=22.11、npm、Android SDK/NDK、JDK 及平台原生工具；iOS 还需要 macOS/Xcode/CocoaPods。完整说明见[运行与打包](docs/build-and-deployment.md)。

```sh
npm ci
npm run config:check
npm run android:test:debug      # 内网 VINote Test + Metro
npm run android:test:apk        # 内网独立 APK
npm run android:vinote:debug    # 公网 VINote Dev + Metro
npm run android:vinote:apk      # 公网正式 APK，需发布签名
```

源码调试依赖 Metro；若手机不能访问开发机，可执行 `adb reverse tcp:8081 tcp:8081`。公网 Debug 使用独立包名，避免调试签名覆盖正式版；两种 APK 均内置 JS。详见[运行与打包](docs/build-and-deployment.md)。

## 验证状态

Android 39 分 10 秒公开长语音样本已完成 20 段转写、失败后续传、分层总结与本机纪要保存，见验收记录。该结果不代表所有会议质量、后台生成或长时间录音完整性已验收。后台录音曾验证服务存活和文件增长，但返回结束后的完整播放仍需补充验收。iOS 已用有线连接的真机完成调试包安装、账号连接和会议音频的前台处理；新后台能力仍需锁屏、切应用和进程终止场景验收。

```sh
npm test -- --runInBand
npm run typecheck
npm run test:scripts
```

父仓库通过 `VINote-app/` Git submodule 固定本仓库提交；先推送 App 提交，再更新父仓库指针。生成物、APK、私人音频、会话和签名凭证不提交。图标源文件在 `assets/branding`；重建脚本 `python scripts/generate-icons.py` 需要 Pillow。

### 会议总结流式传输

总结各阶段使用公网 OpenAI 兼容 SSE，通过原生 XMLHttpRequest 增量接收并显示已接收字数。只有收到完整结束标记且正常结束的结果才写入检查点；断线或截断不会保存半份纪要。原有完整转写和成功事实可继续复用。单次流式请求总上限 15 分钟，仍受服务可用性及后台限制。处理计时另记录完整转写墙钟与总结首内容到达时间；首内容时间包含请求启动、网络及服务等待，并非纯模型延迟。流式传输解决长时间无响应的传输风险，不保证模型或 ASR 请求本身变快。
