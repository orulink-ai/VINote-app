# VINote App 0.1.4

状态：发布源码准备；本轮不生成 APK/AAB/IPA，不代表已发布。用户明确采用 0.1.4，替代历史源码候选 0.2.0；Android versionCode 保持 9（高于 0.1.3 的 8），iOS 营销版本 0.1.4、独立 build 5。

## 两种 Android 包

| 配置 | 内网独立 APK | 公网正式 APK |
| --- | --- | --- |
| 命令 | `npm run android:test:apk` | `npm run android:vinote:apk` |
| 模型直连 | `http://192.168.1.143:9876` | `https://api.orulink.ai` |
| 账号 | 两包均为 `https://supabase-vinote.orulink.ai` | 同左 |
| 内容与飞书 | 两包均为 `https://supabase-vinote.orulink.ai/vinote-api` | 同左 |
| 包身份 | `com.vinoteapp.test`、调试签名 | `com.vinoteapp`、发布签名 |

内网包采用 **LAN 模型直连＋公网内容/飞书**，仍需公网连接。链接或上传笔记由公网内容后端执行，不能声称其模型调用也走 LAN；后端模型 Origin 由服务器配置，App 选定的模型 ID 必须在后端目录可用，否则失败且不自动替换。若要求内容处理也走 LAN，需要另行部署并验收 LAN 内容 API，不把模型入口当作内容 API。

## 校验及验收边界

- 所有内置 JS 的独立 APK/AAB（含旧别名、直接 Gradle standalone）要求显式 generationBaseUrl 和 integrationBaseUrl；Release 继续限定 public 与发布签名。缺失任一服务先拒绝，不执行原生命令。
- 普通 Metro dev=true 保留 loopback 内容入口；独立包 dev=false 使用明确内容地址，Bearer capabilities 验证角色，不恢复同步。
- 现有产品范围参阅历史候选说明及实际验收文档；本轮只做版本/配置与离线验证，没有构建、安装、调用 ASR/LLM 或操作 live 配置。两种新 0.1.4 安装包仍需后续构建与真机核验。
