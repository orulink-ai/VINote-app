# Android ASR transport regression

Production uses `VINoteASRTransport` (thin React bridge), `ASRSocketCore` (OkHttp lifecycle), and `ASRTransportPolicy` (VLA2/queue/error bounds). Other RN WebSockets are unchanged. The APK freezes its trusted ASR Origin from `deployment.apiBaseUrl`; the JVM test instantiates its own core with a loopback-only Origin. There is no production arbitrary-URL switch.

Run from the App root, using existing Gradle/Android caches only:

```powershell
python scripts/check-asr-native-offline.py --local-ws
node node_modules/jest/bin/jest.js __tests__/asrStream.test.ts __tests__/asrTransport.test.ts __tests__/asrReplaySafety.test.ts __tests__/asrFailure.test.ts __tests__/asrDiagnostic.test.ts __tests__/generateRecording.test.ts --runInBand --watch=false
node node_modules/typescript/bin/tsc --noEmit
```

The Python runner compiles actual production Kotlin against cached RN 0.87.1/OkHttp 4.9.2/Android36 APIs. Only the generated BuildConfig field is shimmed for compilation. The pure core then runs on the JVM, without Android Context, a device, credentials or a provider. Compiler heap is 512MiB, network-test heap 256MiB; no Gradle daemon is started.

The loopback peer accepts only a synthetic token and eight planned connections: delayed final plus normal close, actual slow TCP reads/OkHttp queue backlog, actual `send=false` after enqueueing a close, abrupt disconnect, cancellation with a late message, HTTP302 rejection, and two sessions proving disposed/throwing observers cannot block cleanup or subsequent connection in the same core. Tests read the core's socket by test-only reflection to force real enqueue rejection and backlog; production exposes no such hook. The peer independently validates little-endian sequence/length, exact 6402-byte coverage and a single LAST. The long pure coverage test uses 44,049,554 bytes/6883 frames; selected fixtures are generated by executing the current production JS `pcmFrame`, not another implementation. The actual bridge field-writing function is executed with collecting writers on the JVM, verifying close code and failure category separation; this is not a JNI/device test.

Native queue admission is capped at 64KiB and waits up to 10 seconds without replaying a rejected frame. All application submissions await native true enqueue ACKs. An ACK is not remote receipt or final recognition. Native error categories are numeric only: 0 unknown, 1 enqueue rejected, 2 backpressure deadline, 3 timeout, 4 socket exception (not a claimed ECONNRESET), 5 EOF, 6 TLS, 7 connect, 8 DNS, 9 IO, 10 protocol/resource bound. Raw exceptions, host details and tokens are never returned as diagnostics.

Redirects and connection retries are disabled. Ping interval is zero, avoiding a new pong deadline during provider finalization. Normal peer closing is a close-code event, not a fabricated EOF error; the close handshake is replied to and actual onClosed/onFailure awaited (cancel alone after a received close frame was shown by the real test to hang teardown). A final buffered while LAST awaits its true ACK cannot complete before ACK/scope verification and retains the original deadline. Cancellation, ACK false, true IO failure and identity change cannot turn that buffered final into success.

Binary bridge input is capped at 8560 base64 characters before decode; start text at 4096 characters before JSON/UTF8 work. Incoming messages and total queued incoming text are bounded to 8MiB UTF8. Resource release waits for reader cleanup and actual native socket termination; shutdown races are handled by the real executor policy. A new Android APK is required; old APKs fail closed for new ASR jobs instead of silently falling back. iOS keeps its existing transport.
